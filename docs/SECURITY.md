## 概述

本文档详细分析 Adaptive LP Vault 系统中存在的潜在安全风险，并说明已实施的缓解措施。所有风险均经过攻击场景推演和代码级验证。

系统采用多层安全防护架构，包括但不限于：重入保护、滑点保护、TWAP 预言机、权限管理、参数边界限制等。

---

## 已识别风险与缓解措施

### 1. 三明治攻击（Sandwich Attack）

#### 攻击场景

再平衡操作需要在不同流动性场所间转移资金，涉及添加/移除流动性和代币兑换。攻击者可以：

1. 监听内存池（mempool）中的再平衡交易
2. 在再平衡交易前抢先买入，推高目标代币价格
3. 再平衡交易以不利价格执行
4. 攻击者在再平衡交易后卖出，获取利润

这种攻击会导致金库资金以不利价格进行再平衡，损害所有份额持有者的利益。

#### 缓解措施

滑点保护按操作路径覆盖，**用户存取款路径、V2 全路径与 V3 按比例撤出路径设有滑点下限**：

- **用户级滑点保护**：`deposit(weth, usdc, minShares)` 和 `withdrawDual(shares, minWETH, minUSDC)` 要求用户传入最小输出量，防止交易执行时价格偏离预期
- **V2 内部滑点保护**：V2 适配器的 `addLiquidity` 和 `withdrawAll` 内部根据 pair 储备计算滑点下限
- **V3 按比例撤出滑点保护**：Vault 根据当前价格估算预期输出并乘以滑点容忍度，传入 `amount0Min` / `amount1Min`，V3 适配器双重校验
- **TWAP 参考价**：再平衡决策基于 TWAP 时间加权均价，而非瞬时现货价格，降低攻击者操纵参考价的能力
- **激励校验**：再平衡激励发放前校验操作是否产生正向收益，亏损的再平衡不会获得奖励

> ⚠️ **适用边界**：上述滑点保护不覆盖 **V3 再平衡投资（最小输出传 0）与 V3 再平衡全量撤出（`withdrawAll` 无最小输出校验）** 两条路径，该路径存在被三明治攻击的残留风险；缓解依赖冷却期（10/30 分钟）、执行时机不可预测与 TWAP 估值等辅助机制。例外路径详情见 [已知限制与改进方向](#已知限制与改进方向)。

### 2. 重入攻击（Reentrancy）

#### 攻击场景

金库涉及大量代币转账操作（存款、取款、再平衡、领取激励等）。如果某个代币是恶意合约（带有回调函数的 ERC777 或其他非标准代币），攻击者可以：

1. 向金库存款，获得份额
2. 在取款时，恶意代币的 `tokensToSend` 回调中重入金库的 `withdraw` 函数
3. 在状态更新完成前重复取款，盗取超出实际存款的资金

#### 缓解措施

- **ReentrancyGuard**：核心金库 `AdaptiveLPVault` 继承 OpenZeppelin 的 `ReentrancyGuard`，所有涉及外部调用和状态变更的函数均加 `nonReentrant` 修饰符
- **Checks-Effects-Interactions 模式**：所有状态变更（更新份额、记录余额等）均在外部代币转账之前完成
- **标准代币假设**：系统设计假设使用标准 ERC20 代币（WETH、USDC），不支持带有回调的非标准代币
- **SafeERC20**：所有代币操作使用 OpenZeppelin 的 `SafeERC20` 库，安全处理非标准代币的返回值

### 3. 预言机操纵（Oracle Manipulation）

#### 攻击场景

系统的再平衡决策依赖 TWAP 预言机提供的价格数据。如果攻击者能够操纵预言机价格，可以：

1. 通过闪电贷借入大量资金，短期操纵 Uniswap V3 池的现货价格
2. 被操纵的价格被预言机读取，导致错误的再平衡决策
3. 系统以错误的价格区间和资金配比进行再平衡
4. 攻击者利用错误的仓位设置获取利润

#### 缓解措施

- **TWAP 时间加权均价**：使用 Uniswap V3 原生的 TWAP（时间加权平均价格），而非瞬时现货价格。默认采用 30 分钟时间窗口，攻击者需要在整个窗口内维持价格操纵才能影响 TWAP
- **观测窗口可治理**：TWAP 窗口参数可通过治理调整，最小窗口限制防止设置过短的窗口
- **动态冷却期**：波动率 > 50% 时进入紧急模式，冷却期从 10 分钟延长到 30 分钟，降低高波动下的频繁再平衡风险
- **数据源固定**：预言机绑定的 V3 池（`ORACLE_POOL`）为部署时不可变参数（`immutable`），部署后不可更换，防止数据源被替换为攻击者控制的恶意池；当前系统为单一数据源（TWAP），不涉及多数据源切换

### 4. 无常损失（Impermanent Loss）

#### 风险描述

LP 做市本质上存在无常损失风险。当 WETH/USDC 价格发生大幅波动时：

1. 金库的 LP 头寸会自动再平衡为更多贬值代币、更少升值代币
2. 与简单持有两种代币相比，LP 头寸的价值会更低
3. 如果价格持续单向大幅波动，无常损失可能超过手续费收益
4. 用户赎回时可能获得比存款时更少的本金

这不是"攻击"，而是 AMM 做市的固有风险，但会直接影响用户收益。

#### 缓解措施

- **波动率自适应策略**：根据市场波动率动态调整资金配比。高波动时增加 V2 配比（V2 是无限区间，无常损失相对较小），低波动时集中在 V3 高费率池（最大化手续费收益）
- **三层区间做市**：V3 资金分散在窄/中/宽三个价格区间，避免所有资金集中在一个区间。即使价格突破窄区间，中/宽区间仍在赚取手续费
- **动态区间调整**：再平衡时根据当前 TWAP 价格重新设置三层区间的中心价格，确保区间围绕当前价格
- **V2 宽区间摊薄**：部分资金配置在 Uniswap V2（恒定乘积做市，无限区间），用更低的集中度摊薄集中流动性的无常损失
- **手续费收益累积**：做市手续费自动累积到金库资产中，部分抵消无常损失

### 5. 份额价格操纵（Share Price Manipulation）

#### 攻击场景

攻击者利用金库份额计算公式，制造"总资产很大、总份额很小"的状态，让后来存款的人因精度损失拿不到应有的份额，从而窃取存款人资金：

1. 攻击者第一个存款，存入刚好超过灰尘阈值的最小金额（0.000001 WETH + 0.001 USDC），按首存 1:1 计价拿到少量份额
2. 攻击者直接转账（捐赠）大量 USDC 给金库（不经过存款，不要份额）
3. 金库状态变为：总资产 ≈ 很大，总份额 = 极少
4. 后来的用户存入正常金额，按公式计算份额时因精度问题，算出的份额可能很少
5. 用户存了钱但没拿到应有的份额，攻击者手里的份额变得更值钱
6. 攻击者赎回份额，收割存款人的资金

#### 缓解措施

- **双币存款天然抗捐赠**：攻击者要操纵净值，不能只捐赠一种币，必须同时捐赠 WETH + USDC，攻击成本翻倍
- **灰尘阈值保护**：低于 0.000001 WETH / 0.001 USDC 的金额不参与做市，小额操纵空间有限
- **首存 1:1 计价**：第一次存款时 1 USDC 价值 = 1 份额（标准 ERC4626 行为）

> ⚠️ **残留风险**：当前未实现 OpenZeppelin ERC4626 标准的"死份额"机制（第一个地址永久持有一部分份额，防止总份额归零），理论上存在首存攻击残留风险；双币设计显著降低了攻击收益。

### 6. ERC4626 标准接口的第三方兼容性警告（Third-party Compatibility Warning）

#### 问题本质

ERC4626 是单币标准，份额只能赎回一种资产；但本金库装的是 WETH + USDC 两种币。两者存在根本错配：

1. **asset 是 USDC**：按 ERC4626 标准，金库计价资产（asset）设为 USDC
2. **标准接口仅 USDC 路径**：`deposit()` 只收 USDC，`redeem()` 只返回 USDC（WETH 沉淀在金库中）
3. **双币操作走自定义接口**：完整的 WETH+USDC 存取通过 `depositDual()` / `withdrawDual()` 实现，前端只暴露这套

#### 影响范围

- **前端用户**：无影响，前端已封装双币入口，用户直接使用即可
- **第三方钱包/聚合器**：按 ERC4626 标准接入时，会把 `previewRedeem()` 返回的 USDC 纸面估值当成真能赎回的量，可能误判资产构成
- **DeFi 借贷平台**：按标准估值时，会把金库当成 USDC 单币金库，不识别 WETH 敞口

> ⚠️ **注意**：接入第三方前需明确告知双币资产构成，或在合约层实现自动换币封装（存单币自动兑换成双币配对，赎回自动换回单币支付）。

## 已知限制与改进方向

本节记录系统当前存在的已知安全限制。这些限制不影响核心功能正常运行，但在极端市场条件下可能构成风险。

### 1. 滑点保护覆盖不全

系统滑点保护仅覆盖部分操作路径，V3 再平衡相关路径未完全启用：

| 操作路径 | 滑点保护状态 | 说明 |
|---------|-------------|------|
| 用户双币存款 | ✅ 已启用 | 用户指定 `minShares`，前端当前传 0，未设下限 |
| 用户双币赎回 | ✅ 已启用 | 前端默认 1%，用户可传 `minWETH/minUSDC` |
| V2 添加/移除流动性 | ✅ 已启用 | adapter 内部自己算滑点下限（默认 1%），外部传参被忽略 |
| V3 再平衡撤出（`withdrawAll`） | ⚠️ 未启用 | 未传入 `amount0Min`/`amount1Min`，存在三明治攻击残留风险 |
| V3 再平衡加流动性 | ⚠️ 未启用 | `amount0Min`/`amount1Min` 传 0，检查形同虚设 |
| 标准 ERC4626 存取 | ⚠️ 接口限制 | 标准接口签名不支持滑点参数 |

#### 当前缓解措施

- **再平衡冷却期**：正常 10 分钟，高波动（>50%）时 30 分钟，降低被频繁攻击的频率
- **执行时间不可预测**：再平衡由外部激励触发，任何人可调用，执行时间不固定
- **TWAP 估值**：金库总资产估值使用 TWAP 价格而非现货价格，短期价格操纵不影响净值计算

#### 改进方向

- 统一滑点参数来源：V2/V3 适配器均读取金库的 `maxSlippageBps`，不再各自维护
- 为 V3 适配器的 `withdrawAll` 和 `addLiquidity` 增加基于 TWAP 参考价的输出量下限校验
- 治理修改滑点参数时，通过事件通知所有适配器同步更新

### 2. ERC4626 标准接口无滑点保护

ERC4626 标准接口定义的 `deposit(assets, receiver)`、`mint(shares, receiver)`、`withdraw(assets, receiver, owner)`、`redeem(shares, receiver, owner)` 均不包含滑点保护参数。用户通过标准 ERC4626 接口存款时，无法指定最小获得份额；取款时无法指定最小获得资产量。

在价格剧烈波动的场景下，用户提交交易到交易上链的时间差内，金库净值可能发生变化，导致用户实际获得的份额/资产低于预期。

#### 当前缓解措施

- **自定义双币存款接口**：提供 `depositDual()`，支持用户指定最小获得份额
- **自定义双币取款接口**：提供 `withdrawDual()`，支持用户指定最小获得的 WETH 和 USDC 数量
- **前端引导**：前端默认使用自定义接口，用户直接使用即可
- **TWAP 估值**：金库净值使用 TWAP 价格计算，短期价格波动对净值影响有限

#### 改进方向

- 在 ERC4626 标准接口的实现中增加内部滑点校验（基于全局 `maxSlippageBps`）
- 前端明确标注标准接口与自定义接口的区别，引导用户使用带滑点保护的自定义接口
- 考虑实现 ERC-7540（异步金库）标准，将存款/取款拆分为请求和结算两步，从根本上消除时间差风险

### 3. 单币存款无法参与做市

仅存入 USDC 单币时，因 V3 集中流动性需要双币配对，资金无法参与做市，只能闲置等待再平衡时自动兑换。

#### 问题描述

V3 路径因 `_calculateLiquidity` 计算出的流动性为 0（仅单币无法在区间内提供流动性），`addLiquidity` 直接返回不投资。资金利用率为 0，存入的单币资金完全不产生做市手续费收益。

#### 当前缓解措施

- **前端双币存款界面**：前端同时提供 WETH 和 USDC 两个输入框，并在存款页面显著位置提示用户必须同时存入两种代币
- **合约层自动换币**：在 `_investIdleFunds` 中，当仅有单币时，通过 Uniswap 路由将约一半价值的代币兑换为另一种，再进行做市

#### 改进方向

- 优化单币存款体验，引导用户双币存入
- 完善自动换币逻辑，减少换币滑点损耗
