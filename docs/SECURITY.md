## 概述

本文档详细分析 Adaptive LP Vault 系统中存在的潜在安全风险，并说明已实施的缓解措施。所有风险均经过攻击场景推演和代码级验证。

系统采用多层安全防护架构，包括但不限于：重入保护、滑点保护、TWAP 预言机、权限管理、参数边界限制等。

---

## 风险评级说明

| 评级 | 含义 |
|------|------|
| 🔴 高 | 可能导致资金直接损失，需重点防护 |
| 🟡 中 | 可能导致收益受损或系统异常，需关注 |
| 🟢 低 | 影响有限，已有基础防护 |

## 已识别风险与缓解措施

### 1. 三明治攻击（Sandwich Attack）

**风险评级**：🔴 高

#### 攻击场景

再平衡操作需要在不同流动性场所间转移资金，涉及添加/移除流动性和代币兑换。攻击者可以：

1. 监听内存池（mempool）中的再平衡交易
2. 在再平衡交易前抢先买入，推高目标代币价格
3. 再平衡交易以不利价格执行
4. 攻击者在再平衡交易后卖出，获取利润

这种攻击会导致金库资金以不利价格进行再平衡，损害所有份额持有者的利益。

#### 缓解措施

- **取款侧滑点保护**：V2 和 V3 适配器的按比例撤出（`removeLiquidity`）均设置 `amount0Min` / `amount1Min` 参数，由 Vault 根据当前池内储备计算预期输出并乘以滑点容忍度后传入
- **用户级滑点保护**：`deposit(weth, usdc, minShares)` 和 `withdrawDual(shares, minWETH, minUSDC)` 要求用户传入最小输出量，防止交易执行时价格偏离预期
- **V2 内部滑点保护**：V2 适配器的 `addLiquidity` 和 `withdrawAll` 内部根据 pair 储备计算滑点下限
- **TWAP 参考价**：再平衡决策基于 TWAP 时间加权均价，而非瞬时现货价格，降低攻击者操纵参考价的能力
- **激励校验**：再平衡激励发放前校验操作是否产生正向收益，亏损的再平衡不会获得奖励
- **已知限制**：V3 路径的 `withdrawAll` 和 V3 存款当前未设置显式滑点下限，详见[已知限制与改进方向](#已知限制与改进方向)

### 2. 重入攻击（Reentrancy）

**风险评级**：🔴 高

#### 攻击场景

金库涉及大量代币转账操作（存款、取款、再平衡、领取激励等）。如果某个代币是恶意合约（带有回调函数的 ERC777 或其他非标准代币），攻击者可以：

1. 向金库存款，获得份额
2. 在取款时，恶意代币的 `tokensToSend` 回调中重入金库的 `withdraw` 函数
3. 在状态更新完成前重复取款，盗取超出实际存款的资金

#### 缓解措施

- **ReentrancyGuard**：核心金库 `AdaptiveLPVault` 继承 OpenZeppelin 的 `ReentrancyGuard`，所有涉及外部调用和状态变更的函数均加 `nonReentrant` 修饰符
- **Checks-Effects-Interactions 模式**：所有状态变更（更新份额、记录余额等）均在外部代币转账之前完成
- **标准代币假设**：系统设计假设使用标准 ERC20 代币（WETH、USDC），不支持带有回调的非标准代币
- **SafeERC20**：所有代币操作使用 OpenZeppelin 的 `SafeERC20` 库，安全处理非标准代币的返回值

### 3. 预言机操纵（Oracle Manipulation）

**风险评级**：🔴 高

#### 攻击场景

系统的再平衡决策依赖 TWAP 预言机提供的价格数据。如果攻击者能够操纵预言机价格，可以：

1. 通过闪电贷借入大量资金，短期操纵 Uniswap V3 池的现货价格
2. 被操纵的价格被预言机读取，导致错误的再平衡决策
3. 系统以错误的价格区间和资金配比进行再平衡
4. 攻击者利用错误的仓位设置获取利润

#### 缓解措施

- **TWAP 时间加权均价**：使用 Uniswap V3 原生的 TWAP（时间加权平均价格），而非瞬时现货价格。默认采用 30 分钟时间窗口，攻击者需要在整个窗口内维持价格操纵才能影响 TWAP
- **观测窗口可治理**：TWAP 窗口参数可通过治理调整，最小窗口限制防止设置过短的窗口
- **价格偏离校验**：再平衡前校验现货价格与 TWAP 价格的偏离度，偏离过大时暂停再平衡
- **多数据源设计**：架构支持接入多个预言机数据源，当前使用 V3 池 TWAP，未来可扩展接入 Chainlink 等外部预言机

### 4. 无常损失（Impermanent Loss）

**风险评级**：🟡 中

#### 攻击场景/风险描述

LP 做市本质上存在无常损失风险。当 WETH/USDC 价格发生大幅波动时：

1. 金库的 LP 头寸会自动再平衡为更多贬值代币、更少升值代币
2. 与简单持有两种代币相比，LP 头寸的价值会更低
3. 如果价格持续单向大幅波动，无常损失可能超过手续费收益
4. 用户赎回时可能获得比存款时更少的本金

这不是"攻击"，而是 AMM 做市的固有风险，但会直接影响用户收益。

#### 缓解措施

- **波动率自适应策略**：根据市场波动率动态调整资金配比。高波动时增加 V2 配比（V2 是无限区间，无常损失相对较小），低波动时集中在 V3 高费率池（最大化手续费收益）
- **三层区间做市**：V3 资金分散在窄/中/宽三个价格区间，避免所有资金集中在一个区间。即使价格突破窄区间，中/宽区间仍在赚取手续费
- **动态区间调整**：再平衡时根据当前 TWAP 价格重新设置三层区间的中心价格，确保区间围绕当前价格
- **V2 对冲**：部分资金配置在 Uniswap V2（恒定乘积做市，无限区间），作为 V3 集中流动性的对冲
- **手续费收益累积**：做市手续费自动累积到金库资产中，部分抵消无常损失

### 5. 女巫攻击激励（Sybil Attack on Incentives）

**风险评级**：🟡 中

#### 攻击场景

系统设计了去中心化再平衡激励机制，任何人触发再平衡并产生正向收益时，可获得 USDC 奖励。攻击者可能：

1. 创建大量地址（女巫攻击）
2. 用每个地址反复触发小额再平衡
3. 每次再平衡产生微小正向收益，从而累积大量激励奖励
4. 激励资金被攻击者榨取，损害真正的再平衡执行者利益

#### 缓解措施

- **正向收益校验**：激励发放前严格校验再平衡操作是否产生正向收益（金库资产净值增加），亏损或零收益的再平衡不发放奖励
- **最小收益阈值**：设置最小收益阈值，只有再平衡收益超过阈值时才发放激励，防止小额反复操作
- **冷却期**：同一地址触发再平衡后有冷却期，冷却期内再次触发不获得奖励
- **激励比例上限**：激励金额为再平衡收益的固定比例（可治理调整），且有单次上限，防止单次操作榨取大量激励
- **激励资金独立管理**：激励资金存放在独立的 `RebalanceIncentives` 合约中，与金库资产隔离，即使激励被榨取也不影响金库本金

## 已知限制与改进方向

本节记录系统当前存在的已知安全限制，以及对应的改进方向。这些限制不影响核心功能的正常运行，但在极端市场条件或特定攻击场景下可能构成风险。

### 1. V3 再平衡撤出缺少显式滑点保护

**风险评级**：🟡 中

#### 问题描述

`UniswapV3Adapter.withdrawAll()` 在再平衡流程中被调用，用于从所有 V3 仓位撤出流动性。该函数直接调用 `POOL.burn(tickLower, tickUpper, liquidity)` 和 `POOL.collect(...)`，未传入 `amount0Min` / `amount1Min` 参数，也未在函数内部做输出量的下限校验。

相比之下，V2 路径的 `withdrawAll()` 会根据 pair 储备量计算预期输出，并乘以 `(10000 - maxSlippageBps) / 10000` 作为滑点下限。

#### 潜在攻击场景

理论上存在被三明治攻击的风险：

1. 攻击者监听内存池中的 `rebalance()` 交易
2. 在再平衡交易执行前，在 V3 池中大额 swap 推偏现货价格
3. 再平衡交易执行，`withdrawAll()` 按被操纵的价格撤出流动性，金库获得的代币数量偏离公允价格
4. 攻击者反向 swap 平仓获利

#### 当前缓解措施

- **再平衡冷却期**：正常情况下 10 分钟冷却期，高波动率（>50%）时 30 分钟紧急冷却期，降低被频繁攻击的频率
- **执行时间不可预测**：再平衡由外部激励触发，任何人可调用，执行时间不固定，增加攻击者提前布局的难度
- **V2 路径有保护**：V2 适配器的 `withdrawAll()` 有完整的滑点下限计算
- **TWAP 估值**：金库总资产估值使用 TWAP 价格而非现货价格，短期价格操纵不影响净值计算

### 2. V3 存款传入的 minAmount 为 0

**风险评级**：🟢 低

#### 问题描述

`AdaptiveLPVault._investOneRange()` 调用 V3 适配器的 `addLiquidity()` 时，传入的 `amount0Min` 和 `amount1Min` 均为 `0`。

V3 适配器内部虽然有 `require(amount0 >= amount0Min && amount1 >= amount1Min, "V3Adapter: slippage")` 检查，但由于传入的最小值为 0，该检查永远通过，形同虚设。

#### 影响分析

V3 `mint` 是按预先计算好的 `liquidity` 数量存入，实际消耗的 token0/token1 数量由池内当前价格决定。价格偏离的影响主要体现在：

- 实际存入量与预期存入量的差异（dust）
- 多余的未使用资金会留在适配器中，随后通过 `_returnDust()` 退回金库

因此该问题不会导致资金损失，只会导致资金利用效率略有降低。
